# Performance

All numbers here were measured on the machine below with the commands shown. If a
number is not here, it was not measured; nothing in this file is projected.

## Machine and build

| | |
| --- | --- |
| OS | Windows 10 Pro 22H2, 10.0.19045 |
| CPU | 2 × Intel Xeon E5-2697 v4, 16 cores / 16 threads total |
| RAM | 32 GB |
| .NET SDK | 10.0.403 |
| Runtime | .NET 10.0.14 |
| Build | `dotnet publish src/AirGlance.App/AirGlance.App.csproj -c Release -r win-x64 -p:PublishAot=true -p:StripSymbols=true` |
| Rendering | Avalonia Win32 software compositor (the default on Windows in 0.1.1) |
| Date | 2026-11-17 |

Test images are generated by `python tools/make-test-images.py`:

| File | Size | Pixels |
| --- | --- | --- |
| `tools/testdata/photo-24mp.jpg` | 0.55 MB | 6000 × 4000 |
| `tools/testdata/photo-100mp.jpg` | 2.1 MB | 10000 × 10000 |

The benchmark images are gradients, so their JPEG files are smaller than photographs of
the same dimensions. The decode work is dominated by pixel count, not compressed size.

## Method

```powershell
powershell -ExecutionPolicy Bypass -File tools/bench.ps1 -Runs 10
powershell -ExecutionPolicy Bypass -File tools/bench.ps1 -Runs 5 `
  -Image tools/testdata/photo-100mp.jpg
```

Each run starts a fresh process:

```text
AirGlance.exe --bench=startup <image>
```

The app records elapsed time from the process start time reported by the operating
system to:

- `first_window_ms`: the window's `Opened` event.
- `first_frame_ms`: the first render pass that contains image pixels.
- `decode_ms`: the screen-sized decode, overlap included (the first image is decoded on
  a worker while the window is still being built).
- `peak_ws_mb`: the process peak working set at exit.

`tools/bench.ps1` parses those lines and reports the median and p95. The app has no
console, so the script redirects stdout to a temporary file. A NativeAOT build is the
only comparable build; a normal Release build is a JIT app and is much slower.

### 100 MP JPEG at 100%

This is a known heavy path, not a budget target. The workflow was:

1. Launch the published `v0.1.1` `win-x64` artifact with
   `tools/testdata/photo-100mp.jpg`.
2. Wait for the fit-window preview.
3. Press `1` (actual size) and sample `WorkingSet64` once a second.

| Point | Working set |
| --- | --- |
| Fit-window preview | 78.8 MB |
| 1 second after pressing `1` | 435.7 MB |
| 2 seconds after pressing `1` | 836.1 MB |
| Peak during the run | 842.0 MB |
| Steady state at 100% | 836.1 MB |

The window stayed responsive, showed `10000 × 10000 · 100%`, and did not crash. The
full image is 10000 × 10000 BGRA: about 400 MB for the decoded pixels, about 400 MB
for the Avalonia bitmap, plus the preview and cache. The 250 MB fit-window budget does
not apply to this path.

The 0.1.1 full-resolution decode has no time-to-first-pixel stopwatch in the app. The
memory samples show the image was present within the first two seconds on this machine;
the exact latency was not measured.

## Where the startup time goes

`AIRGLANCE_STARTUP_TRACE=1` prints opt-in marks to stderr. One representative 24 MP run
on the software compositor:

```text
main=42.7
app-init=72.2
xaml-loaded=76.0
framework-init=113.2
services-ready=120.3
window-ctor-enter=138.3
window-ctor-ui=152.2
window-ctor-vm=152.9
window-ctor-chrome=154.6
window-ctor-exit=155.2
window-created=155.7
window-opened=192.3
image-initialized=200.7
```

The window content now takes about 14 ms (`window-ctor-ui`). The old MainWindow XAML
build cost about 370 ms; 0.1.1 builds the same chrome in C# and leaves the filmstrip,
information panel and context menu in XAML, loaded after the first frame. The 24 MP
decode (about 57 ms) overlaps window construction and image initialisation. The
remaining gap from `image-initialized` to the first painted frame is about 100 ms.

Earlier builds used the ANGLE/GPU compositor. On this machine that pushed first window
to ~565 ms and first frame to ~790 ms, so 0.1 uses the software compositor on Windows
by default. `AIRGLANCE_GPU_RENDER=1` switches back to the default Avalonia GPU path.
